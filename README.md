# @1chat/agent

Будит вашего ИИ-агента, когда в [1-chat](https://1-chat.ru) приходит сообщение.

```bash
export ONECHAT_API_KEY=sk_1chat_rw_...
npx @1chat/agent --exec "hermes run"
```

Всё. Ни домена, ни сертификата, ни веб-сервера — соединение исходящее.

## Зачем это нужно

У API нет способа разбудить агента, кроме двух: он либо спрашивает сам, либо
вы принимаете вебхук. Спрашивать самому дорого — **каждая проверка языковой
модели это её ход и её токены**, и проверка раз в полминуты обходится в сотню
ходов в час на то, чтобы узнать, что ничего не произошло. Принимать вебхук
дёшево, но требует домена, сертификата и веб-сервера.

Этот клиент — третий путь. Ждёт обычный процесс, который не стоит ничего;
агент запускается только когда сообщение действительно пришло.

```
1-chat  ←(держит соединение)—  @1chat/agent  →  ваш агент
```

## Параметры

| | |
|---|---|
| `--exec <команда>` | что запускать. Событие приходит в `stdin` как JSON |
| `--dialogs <id,id>` | реагировать только на эти диалоги |
| `--state <файл>` | где хранить позицию в потоке, по умолчанию `.state/cursor` |
| `--from now\|begin` | с чего начать при первом запуске |
| `--quiet` | только ошибки в лог |

| Переменная | |
|---|---|
| `ONECHAT_API_KEY` | обязательна, выпускается на странице «API-ключи» |
| `ONECHAT_BASE_URL` | по умолчанию `https://app.1-chat.ru/api` |

Событие уходит в `stdin`, а не аргументом: текст пишет человек, и рано или
поздно в нём окажется всё, что ломает экранирование.

## Как библиотека

```js
import { OneChatClient, isIncomingMessage } from '@1chat/agent'

const client = new OneChatClient({ apiKey: process.env.ONECHAT_API_KEY })

await client.run({
  since: null,
  onCursor: (cursor) => saveSomewhere(cursor),
  onEvent: (event) => {
    if (isIncomingMessage(event)) wakeYourAgent(event)
  },
})
```

## Что он делает за вас

**Хранит позицию в потоке.** Перезапуск не теряет события и не
переобрабатывает старые. Запись атомарная: обрыв в момент сохранения не
оставит битый файл.

**Начинает с текущего момента.** Иначе первый запуск разбудил бы агента на
всей сохранённой истории, и тот написал бы всем подряд.

**Не будит на ваших же исходящих.** Ответить на собственное сообщение — это
переписка с самим собой, в середине которой живой человек.

**Признаёт разрыв.** Если процесс лежал дольше, чем хранятся события, сервер
отвечает `gap`; клиент честно продолжает с текущего момента, а не делает вид,
что ничего не пропустил.

**Отступает при сбоях сети** — пауза растёт до минуты. А на отозванный ключ
останавливается совсем: это не сбой связи, ждать бесполезно.

**Не долбит сервер, если тот отвечает мгновенно.** В норме темп задаёт сервер,
удерживая запрос; но клиент не должен зависеть от чужой добросовестности.

## systemd

```ini
[Unit]
Description=1-chat agent watcher
After=network-online.target
Wants=network-online.target

[Service]
Environment=ONECHAT_API_KEY=sk_1chat_rw_...
WorkingDirectory=/opt/onechat
ExecStart=/usr/bin/npx -y @1chat/agent --exec "hermes run"
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
